# Evidence and assessment

| Criterion | Developing | Secure | Extending |
| --- | --- | --- | --- |
| Java model | Can identify a stage and sprite | Explains fields, methods and one frame of run | Explains object identity and shared clone references |
| Sequencing | Uses a working example | Uses timers/state without blocking a frame | Explains event order and compares runtimes |
| Testing | Runs once and watches | Tests boundaries, collisions and scoring with evidence | Adds a deterministic behavioral check |
| Saving and transfer | Saves a file | Reopens a project with its assets and chosen flavor | Explains a compatibility limitation and adapts it |
| Reflection | Describes the change | Gives evidence and reasons in the diary | Compares alternatives and justifies the choice |

Assess explanations and the student's own modification. Finished checkpoints
are examples, not assessment submissions. Preserve existing reflection questions.
