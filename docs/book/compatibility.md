# Browser compatibility

Desktop library: **5.8.0**. Browser implementation: **5.8.0-browser.1**.

Generated by `scripts/browser-compatibility.py`. [Download the machine-readable contract](/compatibility.json).

Public constructors and method groups documented by the Javadoc doclet. Overload matching uses simple erased parameter names, constructor kind and static/instance kind; qualified parameter and return types are recorded. This is a source compatibility inventory, not a binary compatibility guarantee.

## Library flavors

| Flavor | Embedded libraries | List type |
| --- | --- | --- |
| standard | `scratch` | `java.util.List` |
| nrw | `scratch, nrw` | `nrw.List` |

## Limits of this revision

- Availability describes documented member groups and browser declarations. Compilation tests do not prove rendering, timing or complete behavioral parity.
- Fragment shaders use WebGL. Custom vertex shaders are desktop-only; the browser substitutes its default vertex shader.
- File-system, pixel-buffer, recorder and Tiled APIs are desktop-only. Browser declarations can be stubs that report the limitation.
- Reference examples are compiled with the standard flavor. Existing NRW runtime fixtures and a separate declaration inventory cover the NRW flavor.
- Java compiler dialect differences also apply, including Java package access and unsupported standard-library methods.
